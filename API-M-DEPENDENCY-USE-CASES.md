# WSO2 API Manager dependency and use-case catalog

Analyzed pack: `/Users/pasant/Desktop/Packs/wso2am-4.7.0`

This document is the upgrade-test selection catalog for the third-party
dependencies packaged in this API-M distribution.

## Coverage

- Third-party dependency/version records: **374**
- Bytecode-confirmed paths to WSO2 components: **220**
- Declared OSGi paths: **25**
- Packaged-only records requiring manual tracing: **129**

## How to use this catalog

1. Find the upgraded dependency in the dependency table.
2. Use `Primary API-M feature areas` as the focused regression-test set.
3. Review `possible_transitive_feature_areas` in the CSV for broader risk.
4. Confirm actual package wires on every affected runtime profile.
5. Trace the reported WSO2 class to its activation point in matching source.
6. Run the baseline scenario below and add version-delta boundary tests.

A declared OSGi edge is impact evidence, not proof that a code path executes.
Webapp, bootstrap, Tomcat and CXF copies use separate classloaders and must be
tested independently.

## Baseline regression scenarios

| API-M feature area | Baseline upgrade scenario |
|---|---|
| API design and OpenAPI | Validate and import file, URL, and inline OAS 2.0/3.0/3.1 definitions; assert schema, resources and security survive parse/export; include invalid and complex input. |
| Publisher and API lifecycle | Create, update, revise, deploy, publish and delete REST APIs/API Products through Publisher v4; assert generated artifacts and lifecycle responses. |
| Developer Portal and subscriptions | Discover an API, create an application, subscribe, generate credentials and invoke; assert visibility, subscription and key state. |
| Admin and policy management | Create/update/read/delete affected Admin policies, key managers or gateway environments; assert REST contracts and propagation. |
| Classic Gateway request flow | Deploy and invoke an API over HTTP and HTTPS; assert authentication, routing, mediation, headers, payload, backend errors and gateway logs. |
| Platform and federated gateways | Register the affected gateway type, deploy/undeploy an API, inspect generated deployment artifacts, and verify discovery/synchronization where supported. |
| OAuth, tokens and API security | Exercise relevant OAuth grants, JWT/API-key validation, JWKS rotation, scopes, expiry, revocation and negative authorization cases. |
| Throttling and Traffic Manager | Apply subscription/application/API/resource limits; cross the quota and recovery window; verify decisions and distributed event propagation. |
| API governance | Attach a ruleset and validate passing/failing YAML and JSON definitions during create, import, edit and APICTL dry-run; assert rule locations and severity. |
| Analytics and event publishing | Invoke success/failure requests with representative metadata and verify emitted analytics events, user-agent fields, batching and failure isolation. |
| GraphQL APIs | Import schema, deploy, execute query/mutation/subscription, and verify validation, security and GraphQL-specific throttling. |
| WebSocket, WebSub and streaming APIs | Deploy and exercise handshake, message/event delivery, authentication, throttling, reconnection and cleanup for the affected streaming protocol. |
| AsyncAPI and Solace | Import/export the AsyncAPI or Solace definition, create/deploy the API, and assert semantic preservation and broker interaction. |
| MCP and AI Gateway | Create/deploy the affected MCP or AI API, invoke tool/model operations, and verify policies, security, limits, streaming and analytics. |
| Workflows and notifications | Trigger the affected approval/notification workflow, verify pending/approved/rejected transitions, callback handling and message delivery. |
| SOAP, WSDL and XML processing | Import WSDL/SOAP API, invoke representative operations and faults, and verify XML serialization, namespaces, schema validation and SOAP-to-REST mediation. |
| HTTP clients, transports and TLS | Test inbound and outbound HTTP(S), TLS handshake/trust, redirects, proxy, pooling, timeout, chunking, compression and large payload behavior used by the affected component. |
| Database and persistence | Run affected CRUD and transaction flows on each supported relevant DB; verify migration, rollback, pooling, constraints and concurrent updates. |
| Caching, clustering and distributed state | Exercise cache hit/miss/invalidation and, where applicable, multi-node replication, failover, stale-data and concurrent-update behavior. |
| JMS, Kafka and event broker | Publish/consume affected messages; verify reconnect, acknowledgement, ordering, retry, serialization and broker-unavailable behavior. |
| Configuration and startup | Start every affected API-M profile with default and representative custom configuration; assert no unresolved bundles, service activation errors or configuration parse failures. |
| Logging and observability | Exercise startup and request/error logging; assert formatting, masking, routing, rollover and absence of logging-provider/classloading errors. |
| Management web runtime | Start the Control Plane, log into each affected portal/REST webapp, exercise session and upload/download paths, and inspect servlet/Tomcat errors. |
| Serialization and data binding | Round-trip representative REST/config payloads including unknown/null/Unicode fields; verify compatibility, validation errors and stable response shape. |
| OSGi and Carbon platform | Start each affected profile, capture resolver wires, check bundle states/DS services, restart cleanly, and verify no split-package or classloading failures. |
| Cryptography and key stores | Exercise keystore/truststore loading, signing, verification, encryption and supported TLS algorithms/providers, including invalid and rotated keys. |
| Search, indexing and registry | Create/update/delete/search APIs and documents; verify indexing, registry persistence, tenant isolation and restart consistency. |
| Scheduled tasks and concurrency | Run the affected scheduled/background task through success, retry, overlap and shutdown; verify thread cleanup and persistent state. |
